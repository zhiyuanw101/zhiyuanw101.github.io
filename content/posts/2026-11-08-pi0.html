A robot policy maps what a robot observes to the actions it takes next. $\pi_0$ (“pi-zero”) from Physical Intelligence (Black et al. 2024) is one policy for many robots and long dexterous tasks, such as laundry folding.

The central idea of $\pi_0$ is flow matching. The network does not output actions. It outputs a velocity field: for a noisy action chunk, it gives the direction in which the chunk must change. Sampling starts from random noise and follows this field until the noise becomes an action chunk. This post explains this idea first, and then the model and the training recipe around it.

Notation

SymbolMeaning
$\mathbf{o}_t$Observation at control step $t$: camera images, language command and robot state.
$\mathbf{A}_t$Action chunk: the actions for the next 50 control steps.
$\tau$Flow matching time in $[0, 1]$: $\tau = 0$ is noise, $\tau = 1$ is data.
$\boldsymbol{\epsilon}$Noise chunk with independent $\mathcal{N}(0, 1)$ entries, the same shape as $\mathbf{A}_t$.
$\mathbf{A}^\tau_t$Noisy action chunk at time $\tau$.
$\mathbf{v}_\theta$Velocity predicted by the network with parameters $\theta$.

The Problem

At each control step $t$, the policy receives an observation $\mathbf{o}_t$: camera images, a language command and the joint state of the robot. It outputs an action chunk $\mathbf{A}_t$, the actions for the next 50 control steps.

One observation often allows more than one correct action. For example, a robot can move around an obstacle on the left or on the right, and the demonstrations contain both. Regression with a squared error predicts the mean of the two, which is a path through the obstacle. The policy must therefore model the distribution of actions and draw one sample from it.

The policy
$$ \mathbf{A}_t \sim p_\theta(\mathbf{A}_t \mid \mathbf{o}_t) $$

One inference draws one sample: a chunk of 50 future actions for the current observation.

Flow Matching: Learning a Velocity Field

The idea

Treat one action chunk as one point in a high-dimensional space. The demonstrations form a cloud of data points, and Gaussian noise forms a second cloud. Flow matching learns a velocity field that moves every noise point to a point of the data cloud.

The flow matching time $\tau \in [0, 1]$ measures the progress of this movement. The network $\mathbf{v}_\theta(\mathbf{A}^\tau, \tau, \mathbf{o}_t)$ receives the current point, the time and the observation. It returns the velocity of the whole chunk at that point.

The policy as a flow
$$ \mathbf{A}^0 = \boldsymbol{\epsilon} \sim \mathcal{N}(\mathbf{0}, \mathbf{I}), \qquad \frac{d\mathbf{A}^\tau}{d\tau} = \mathbf{v}_\theta(\mathbf{A}^\tau, \tau, \mathbf{o}_t) $$

The action chunk is the end point $\mathbf{A}^1$ of this path.

The rest of this section answers two questions. How does the network learn the field from demonstrations? How does a robot follow the field to get a chunk?

Training: one straight path per example

The demonstrations give data points, but no velocities. Flow matching builds a velocity target from each example. Draw a noise chunk $\boldsymbol{\epsilon}$ and a time $\tau$, and connect $\boldsymbol{\epsilon}$ to the demonstrated chunk $\mathbf{A}$ with a straight segment (Fig. 1).

Noisy action chunk
$$ \mathbf{A}^\tau = \tau \mathbf{A} + (1 - \tau)\boldsymbol{\epsilon} $$

On this segment, the velocity is constant: $d\mathbf{A}^\tau / d\tau = \mathbf{A} - \boldsymbol{\epsilon}$. The network receives $\mathbf{A}^\tau$ and learns to predict this velocity with a squared error.

Flow matching loss
$$ L(\theta) = \mathbb{E}_{(\mathbf{o}_t, \mathbf{A}_t),\ \boldsymbol{\epsilon},\ \tau} \Big\| \mathbf{v}_\theta(\mathbf{A}^\tau_t, \tau, \mathbf{o}_t) - (\mathbf{A}_t - \boldsymbol{\epsilon}) \Big\|^2 $$

This is the only loss of $\pi_0$.

The paper writes this loss without $\tau$ as an input of $\mathbf{v}_\theta$, but the model and the code use it ().

Section IV of the paper writes the network as $\mathbf{v}_\theta(\mathbf{A}^\tau_t, \mathbf{o}_t)$ and takes the expectation over $\mathbf{A}_t$ and $\mathbf{A}^\tau_t$ only. The time $\tau$ is an input of the network (Appendix B), and the expectation also runs over $\tau$.

The paper states the path as $q(\mathbf{A}^\tau_t \mid \mathbf{A}_t) = \mathcal{N}(\tau\mathbf{A}_t, (1-\tau)\mathbf{I})$, which has variance $1 - \tau$. The sampling rule $\tau\mathbf{A}_t + (1-\tau)\boldsymbol{\epsilon}$ gives variance $(1-\tau)^2$. The code uses the sampling rule.

From crossing segments to one field

Training pairs each data point with random noise, so the segments of different pairs cross (Fig. 2, left). Many segments pass through the same point $\mathbf{x}$ at the same time $\tau$, with different directions. The network has one output for that point, and the squared error is smallest at the mean of these directions ().

The learned velocity field
$$ \mathbf{v}^*(\mathbf{x}, \tau, \mathbf{o}) = \mathbb{E}\big[\mathbf{A} - \boldsymbol{\epsilon} \;\big|\; \mathbf{A}^\tau = \mathbf{x},\ \mathbf{o}\big] $$

The minimizer of the flow matching loss: at each point, the average direction of all training segments through it.

Fix $\tau$, $\mathbf{o}$ and a point $\mathbf{x}$, and let $\mathbf{U} = \mathbf{A} - \boldsymbol{\epsilon}$ be the target. For any output $\mathbf{v}$,

$$ \begin{aligned} \mathbb{E}\big[\|\mathbf{v} - \mathbf{U}\|^2 \mid \mathbf{x}\big] &= \big\|\mathbf{v} - \mathbb{E}[\mathbf{U} \mid \mathbf{x}]\big\|^2 \\ &\quad + \mathbb{E}\big[\|\mathbf{U} - \mathbb{E}[\mathbf{U} \mid \mathbf{x}]\|^2 \mid \mathbf{x}\big] \end{aligned} $$

Only the first term depends on $\mathbf{v}$, and it is zero at $\mathbf{v} = \mathbb{E}[\mathbf{U} \mid \mathbf{x}]$. The second term remains, so the training loss does not decrease to zero.

For one-dimensional data with the values $-2$ and $+2$ at equal probability, the field has a closed form. Given $A$, the point $A^\tau$ is normal with mean $\tau A$ and standard deviation $s = 1 - \tau$. Bayes’ rule gives $\mathbb{E}[A \mid A^\tau = x] = 2\tanh(2\tau x / s^2)$, so $v^*(x, \tau) = \big(2\tanh(2\tau x / s^2) - x\big)/s$. Figures 2 and 3 use this formula.

Further reading: Flow Matching for Generative Modeling (arXiv) and Flow Straight and Fast (arXiv).

The averaged field gives paths that do not cross (Fig. 2, right). Lipman et al. (2022) and Liu et al. (2022) prove that these paths carry the noise distribution to the data distribution. Each training pair gives a straight target. The learned field is the average of all targets, and its paths are curved.

Sampling: follow the field

To generate a chunk, draw noise and follow the field with forward Euler steps.

Sampling with forward Euler
$$ \mathbf{A}^{\tau + \delta} = \mathbf{A}^\tau + \delta\, \mathbf{v}_\theta(\mathbf{A}^\tau, \tau, \mathbf{o}_t) $$

$\pi_0$ uses $\delta = 0.1$: ten steps from $\tau = 0$ to $\tau = 1$.

Each step updates the whole chunk at once, so generation is not autoregressive. In Fig. 2, a path that starts near 0 first stays near 0, where both data values are equally likely. Near the middle of the time range, it moves toward one value, and then it goes to that value on a straight line.

The observation shapes the field

The observation changes the field, and the starting noise selects one path in it (Fig. 3). When the scene allows one action, all paths end at that action. When the scene allows several actions, the starting noise decides which one the robot executes.

Flow matching belongs to the same family as diffusion models (). During training, $\pi_0$ draws $\tau$ more often near the noisy end than near the data end ().

Diffusion models (Sohl-Dickstein et al. 2015; Ho et al. 2020) add noise to data in many small steps. A network learns to remove it, usually by predicting the noise $\boldsymbol{\epsilon}$. Flow matching and rectified flow (both 2022) use a straight path from noise to data and predict the velocity. Sampling is deterministic after the choice of the starting noise.

On the straight path, the three prediction targets carry the same information. Given $\mathbf{A}^\tau$ and $\tau$, a velocity $\mathbf{v} = \mathbf{A} - \boldsymbol{\epsilon}$ gives $\mathbf{A} = \mathbf{A}^\tau + (1-\tau)\mathbf{v}$ and $\boldsymbol{\epsilon} = \mathbf{A}^\tau - \tau\mathbf{v}$.

Diffusion Policy (Chi et al. 2023) and Octo (Octo Model Team 2024), two baselines in the paper, generate actions with diffusion.

The original flow matching papers draw $\tau$ from the uniform distribution. Esser et al. (2024) give more weight to the middle of $[0, 1]$ for images. $\pi_0$ uses

$$ p(\tau) = \operatorname{Beta}\!\Big(\frac{s - \tau}{s};\ 1.5,\ 1\Big), \qquad s = 0.999 $$

The density is largest at $\tau = 0$ and decreases to zero at $\tau = s$. The authors argue that an observation constrains the actions much more than a text prompt constrains an image. The mean action is therefore the hard part, and the network learns it at the noisy end.

Model Architecture

$\mathbf{v}_\theta$ is one transformer over one token sequence (Fig. 4). Image and text tokens use the weights of PaliGemma (Beyer et al. 2024), a vision-language model (VLM) with 3 billion parameters. The robot state and the 50 noisy actions use a second, smaller set of weights, the action expert. The two sets of weights interact only in self-attention.

A block-causal attention mask controls what each token sees. Image and text tokens attend only to each other, as in the pre-training of PaliGemma. Action tokens attend to all tokens, and to each other in both directions. The observation tokens therefore do not depend on the noisy actions, and the model computes them once per chunk.

The time $\tau$ enters each action token through a small MLP. The design follows Transfusion (Zhou et al. 2024), which trains one transformer on discrete and continuous tokens ().

Transfusion trains one transformer with two losses: next-token cross-entropy for text and a diffusion loss for continuous image latents. $\pi_0$ keeps the continuous part only, and its language model produces no text output.

The authors describe the two sets of weights as a mixture of experts with two experts. The token type selects the expert, and no router is learned. The authors report that the separate weights for robot tokens improve performance.

Training and Inference

One training step draws an example, a noise chunk and a time, and runs one forward pass. Training runs no integration, as in language model training. The open-source code uses the opposite direction of time ().

In the code, $t_{\text{code}} = 1 - \tau$, so $t_{\text{code}} = 1$ is noise and $t_{\text{code}} = 0$ is data. The target is $\boldsymbol{\epsilon} - \mathbf{A}$, and sampling starts at $t_{\text{code}} = 1$ with the step $-1/10$. The results are the same. Further reading: openpi (GitHub), file src/openpi/models/pi0.py.

One inference runs the observation tokens once and the action expert 10 times. It takes about 73 ms on one GPU, which is longer than one control step. The robot therefore executes the first part of each chunk without new images, and then runs inference again.

Data and Training Recipe

Pre-training uses about 10,000 hours of robot data from 7 robot configurations and 68 tasks, plus open data sets. Post-training fine-tunes the model on curated data of one task. Both stages use the same flow matching loss.

Curated data shows a fluent strategy, but it contains few mistakes, so a model trained only on it does not learn to recover. Diverse pre-training data contains mistakes and corrections. The combination gives fluent behavior with recovery, as in the pre-training and post-training of large language models.

Training recipe

Pre-train on diverse data from many robots and tasks for broad coverage and recovery behavior. Post-train on curated data of one task for a consistent, fluent strategy.

Results

All experiments run on real robots, and the score is the task progress from 0 to 1.

  • Without post-training, $\pi_0$ scores higher than OpenVLA (Kim et al. 2024) and Octo on all five test tasks.
  • On new tasks, the pre-trained $\pi_0$ often scores higher than the same model trained from scratch.
  • On tasks of 5 to 20 minutes, such as laundry folding and box building, the full recipe scores highest in all comparisons.

Quick Summary

  • $\pi_0$ samples a chunk of 50 actions from $p(\mathbf{A}_t \mid \mathbf{o}_t)$, because one observation can allow several correct actions.
  • The network learns a velocity field. For a noisy chunk, a time and an observation, it gives the direction in which the chunk must change.
  • Training draws a straight segment from noise to a demonstrated chunk and regresses the constant velocity $\mathbf{A} - \boldsymbol{\epsilon}$. The minimizer is the average velocity at each point.
  • Sampling starts from noise and follows the field in 10 Euler steps. The observation shapes the field, and the starting noise selects one sample.
  • The model is PaliGemma plus a small action expert, which share self-attention. Pre-training on diverse data and post-training on curated data give fluent behavior with recovery.
